# T1 论文原文工作台

从文本型PDF提取肿瘤影像外观原文，保留出处、必要语境、整幅Figure和原图注，供逐篇核对与导出。正式主流程为B0；F仅保留实验实现与历史对照。

当前界面采用用户选定的Linear式简洁工作台；[本轮侧栏任务操作记录](docs/acceptance/sidebar-task-actions-2026-11-13/report.json)已同构建上线并完成限定线上只读核验。[前轮文案、左栏类型与AGICTO模型配置记录](docs/acceptance/ui-model-switch-2026-11-13/report.json)保留前轮同构建上线与限定工程核验。[目录导入与任务类型记录](docs/acceptance/folder-task-types-2026-11-13/report.json)保留前轮目录入口和类型标记核验；[批量提交与刷新记录](docs/acceptance/batch-submission-2026-11-13/report.json)与[单箭头居中刷新记录](docs/acceptance/batch-submission-2026-11-13/refresh-center.json)保留前轮交付时点，[既有界面记录](docs/acceptance/linear-ui-2026-11-12/report.json)保留原布局验收。默认保留/排除、连续原文及三导出业务仍按[既有工程记录](docs/acceptance/retention-workflow-2026-11-11/report.json)。S2医学、完整独立S6和S7完整真实门槛未升级；模型仅用户点击开始，旧自主额度保持关闭。

## 操作流程

1. 使用“选择文件”多选PDF，或“选择文件夹”递归筛选用户电脑文件夹及子文件夹中的PDF（扩展名不区分大小写）；界面显示识别PDF和跳过其它文件数量，其它文件不上传。每批最多20篇、50MiB/篇；超过当前可添加数时整次不加入并保留原清单，按提示选择子文件夹或多选分批；没有PDF会明确提示。逐文件串行上传，独立显示成败，可重试失败项或移除未提交项；上传不调用模型，界面提示“先上传，再根据下方范围开始抽取。”同名文件不合并，目录相对路径作为默认标题便于区分。三层范围默认不限；真实医学目录未核，未配置受信目录时限制项不可用，空选/失效不自动放宽。浏览器不支持目录选择时仍可使用多选文件。
2. 点击开始，每篇独立run，沿用2个FIFO槽和原每run预算。首次开始按有效未移除成员数固定“单篇”或“批量”，包含尚可重试的上传失败项；类型、范围和模型配置一起固定，批量局部失败后仅剩1项重试仍显示批量。专用单篇开始入口仍为单篇。类型标记仅在左侧论文列表显示，与实际打开的运行或历史输出一致：显式选择优先，否则按点击论文时的默认运行（先有候选的运行，再该论文首个运行）显示；既无运行也无输出时不标记，缺submission的旧运行或历史输出显示“类型未记录”。工作台标签切换保留本批；关闭或整页重载不恢复未提交草稿，已上传论文和已提交任务仍持久保留，后台不因此取消。失败/中断保留成果，新建运行从头处理，不自动续跑。手动“刷新工作台”在论文列表与当前内容原位显示灰罩，唯一等待箭头位于可视工作区正中心，忙时隐藏右上按钮图标；实际读取完成后用悬浮提示反馈成功或失败，不推挤布局或重置选择，原PDF和滚动位置保持。
3. 在“抽取结果”阅读连续原文和明确配图，使用醒目的“排除此条”或“恢复保留”按钮取舍。同源成员、来源版本与高级操作集中在“说明”；必要系统说明集中显示，不要求填写备注。真实来源、字形或未完处理问题仍可查看，原片段/指纹和主目标/背景语义保持。
4. 结果默认保留；排除可恢复，旧有效拒绝延续，修改内容不会悄悄恢复。可选来源/标签修订从“说明”进入并记录修订人；日常取舍无需审核人或理由。开发抽样、医学核验与旧评价独立，默认保留不表示医学批准，保留背景仍是背景。
5. 按篇下载“保留结果”JSONL、CSV或证据包，直接包含当前未排除内容，无逐条或整篇确认。常规导出提示保持简短；来源/字形和处理完整性按实际状态披露。PDF缺失或SHA不符仍阻止新抽取与保留结果导出，待核图片不自动获批准。

左侧每篇论文旁的“⋯”为“任务操作”：按时间、状态、模型与任务ID核对后，点击所需任务的“取消此任务”，每次只取消一个运行并保留已有结果。打开菜单及取消另一篇论文的任务不切换当前结果；取消中、真实结果及失败/刷新问题用浮层提示，可从失败提示重试。已结束的任务不再提供取消入口；“汇总核验中”保留入口，由后端区分真实可取消阶段与已结束的收尾，并据实提示；菜单也可打开既有“任务与历史”。

## 模型与限额

默认模型已选AGICTO **gpt-6-luna / medium / openai-responses**，这是成本方向与工程兼容性选择。默认模型已选定，普通服务已启用，用户手动开始后按每run独立限额执行；已有结果仍可查看、审核与导出。 普通服务接纳gpt-6-luna→data-zone-standard-gpt-6-luna精确返回对，依据用户/委托部署选择；旧igpt厂商确认独立留证，不将新对或底层权重写成已认证，其它未知返回名仍停止。

在“新任务”顶部的“抽取模型”中选择AGICTO模型，或点击“添加模型”填写模型ID并保存选择；高级设置折叠提供Responses/Chat Completions、medium/不发送推理参数、本地上下文与输出上限。新增默认上下文32768、输出4096 token，使用Chat Completions且不发送推理参数；这些是本地守卫配置，不证明供应商容量或模型可用性，本轮未进行真实模型调用验证。配置以不可变档案保存，修改时另存新档案；新增模型只接受其model_id的精确返回，不继承Luna别名。选择只影响新任务；准入、排队、重试和同一批次首启均使用冻结的范围、submission及模型快照。

普通用户仅点击开始；上传、查看、审核和导出不发模型请求，不填写实验授权表。每个新run独立最多**80请求、200万输入token、12万输出token、30分钟执行时间**；已实现2个FIFO执行槽，第三任务持久排队且可取消；重启标中断，不自动续跑。 排队等待单列，执行时间包含CPU解析、模型和全文汇总。有限重试计入本次预算，无自动循环或旧试验余额继承。请求/时间受应用硬限，token按本地预留及供应商回报计量；不承诺供应商货币账单绝对截断。

服务器管理provider、密钥、端点、目录及硬限额，前端仅在现有AGICTO内新增/选择模型配置；添加配置不发模型请求。克隆示例保持模型关闭；当前实例的实际模型/额度/启用状态以页面及服务capabilities为准。医学目录的配置能力与目录内容是否经真实医学核验分开。

## 目录与证据

- `apps/server/`、`apps/pi-web/`：Fastify与唯一Next工作台；`packages/`为受限Agent、契约及交付核心。
- `services/pdf-parser/`：Docling CPU及原文锚点；`deploy/`：容器、模型校验、备份恢复与宿主配置。
- `runtime-data/`：SQLite、源PDF、IR、整图、版本、独立保留状态、旧审核及每run账本；隔离测试库不替换生产库。
- `evaluation/`、`docs/acceptance/`：来源与冻结实证，部分文件被生产工作台直接引用，不按历史目录整体删除。
- `third_party/pi-web/`：固定上游源码、SHA及MIT来源。上游终端/任意文件/凭证和通用coding API不作为T1业务接口。
- 开发计划只在[主计划](../方案/子任务T1/T1智能体开发计划.docx)与[执行说明](../方案/子任务T1/T1开发执行说明.docx)维护，本页仅为工程使用说明。
